# CLAUDE.md — «Деньги» (учёт доходов и расходов SUB PROFI)

ПУБЛИЧНЫЙ репозиторий: всё здесь видит весь интернет. Ни ПИН-кодов, ни ключей, ни адресов служебных таблиц и папок в этом файле и в новых правках быть не должно.

## Что это и кто пользуется
Мобильное приложение (PWA) для учёта денег ООО «SUB-PROFI»: расходы, доходы, вложения, переводы между кассами, остаток средств, отчёты.
Сотрудники записывают расходы и доходы; руководитель видит все записи, отчёты, может править и отменять любые операции.
Интерфейс на русском и узбекском (латиницей), валюта — сум (UZS). Данные хранятся в Google Таблице (листы «Операции», «Справочники», «Отчёты»).

## Где работает и как обновляется
- Сайт: GitHub Pages, ветка `main`; изменения появляются через 1–2 минуты.
- Сервер: Google Apps Script над таблицей, файл `apps-script/Code.gs` (в шапке указана «версия 5»). Адрес сервера — в `index.html`, `CONFIG.API_URL`; не менять и не копировать в другие файлы.
- Код из `Code.gs` на GitHub сам не обновляется: его нужно вставить в Apps Script таблицы и сделать «Начать развертывание -> Управление развертываниями -> Новая версия».
- ПРАВИЛО: при каждом изменении `index.html` поднимать версию кэша `CACHE` в `sw.js` (сейчас `uchet-v6`). Иначе телефоны не обновятся. Отдельного `APP_VER` в этом приложении нет.
- Автоматика продаж: функция `syncSales` каждые 5 минут переносит оплаченные заказы бота продаж в «Деньги» (включается один раз через `installSalesSync`).

## Карта файлов
- `index.html` — всё приложение: вход, плитки частых трат, ввод суммы, история, отчёты, баланс, переводы ru/uz. Настройки — блок `CONFIG` вверху.
- `apps-script/Code.gs` — сервер: `doPost` (действия users, setPin, init, add, history, cancel, edit, report, balance), проверки `validateOp_`, роли, `syncSales`.
- `sw.js`, `manifest.webmanifest`, `icons/` — установка и офлайн.

## Что нельзя ломать
- Защита от двойной записи: приложение создаёт `id` операции (`newId`), сервер при повторе с тем же `id` не создаёт дубль (`addOp_`, ответ `duplicate`). Не убирать и не создавать новый `id` при повторной отправке.
- Роли: сотрудник может записывать только «Расход» и «Доход» (`STAFF_TYPES`); «Вложение», «Перевод» и отчёты (`report_`) — только руководитель. Сотрудник правит только свои записи, отменяет свои в течение `CANCEL_MINUTES` (10 минут); руководитель — любые.
- Вход: пользователь из справочника + PIN (4 цифры при первом создании). Без PIN войти нельзя; задать PIN может сам сотрудник только пока он пуст. Не ослаблять `auth_` и `setPin_`.
- Проверки на сервере (`validateOp_`): сумма больше нуля и не больше `MAX_AMOUNT` (защита от лишних нулей), статья и касса только из справочника, дата не в будущем, для расхода обязательно наименование; перевод — между разными кассами.
- Запись и правка идут под `LockService`; операции не удаляются — отмена ставит статус «Отменена», отменённые не считаются в остатке.
- Предупреждение, если сумма в `CONFIG.WARN_FACTOR` раз больше обычной по статье.
- НДС: цены заказов без НДС 12%; в «Деньги» продажа по способу «Перечисление» записывается с НДС 12% (`saleAmt_`), наличные и карта — без НДС. Автоматика не перезапишет запись, которую руководитель поправил в приложении.
- PIN в листе «Справочники» хранится отпечатком sha256 (`pinHash_`, с 26.10.2026; старые открытые PIN переводятся сами при входе). После 5 неверных попыток вход закрыт на 10 минут (`ERR_LOCKED`). На телефоне PIN лежит в `localStorage` — не выводить его в отчёты, логи, ответы сервера.
- Записи за период до `SALES_FROM` автоматика продаж не берёт — не менять без владельца (начало учёта).

## Как проверять перед публикацией
1. `python -m http.server 8000`, открыть `http://localhost:8000/`; ширина окна 390 px: нет прокрутки вбок, кнопки крупные.
2. Консоль браузера — без красных ошибок; переключить язык ru/uz.
3. Не создавать пробных записей на рабочем сервере без согласия владельца: записи попадают в настоящие деньги и отчёты.
4. `Code.gs` проверяется в редакторе Apps Script (Сохранить — без ошибок); лучше сначала на копии таблицы.
5. Поднять `CACHE` в `sw.js`.

## Как откатить
- `git revert <коммит>` и отправить в `main` (снова поднять версию кэша).
- Серверный код: Apps Script -> Управление развертываниями -> предыдущая версия.
- Перед правками рабочей таблицы — копия таблицы (Файл -> Создать копию).

## Правила работы с владельцем
- Владелец не программист: простыми словами, без терминов, коротко, по шагам.
- Перед любыми изменениями, которые касаются денег, записей, касс, ролей и PIN, — сначала спросить.
- Не коммитить и не пушить без явной просьбы; репозиторий публичный.
- Секреты и идентификаторы таблиц — только в свойствах скрипта, не в коде и не в этом файле.
- Нет данных — писать «уточнить» и спрашивать, не выдумывать.
